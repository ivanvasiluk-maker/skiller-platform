# Live backend QA — 1 ноября 2026

## Результат

Поведение 1.4. Два изолированных прогона по 27 шагов и 7 реальных API-вызовов прошли. Второй прогон после исправления прямого fallback прошёл полностью. Модель gpt-4.1-mini, store=false; только синтетические случаи. Общий ledger компонентных и backend-проверок: 222 запроса, расчётный расход $0.1054064 из разрешённых $5; это оценка по токенам, не счёт и не лимит аккаунта.

## Что проверено

- Настоящие trainerCommand, trainerState, D1 и оркестратор; отдельная временная тестовая база, без production.
- Для Марши, Бека и Скиннера: история диалога, передача поправки в модель, повтор requestId без второго API-вызова, повторное открытие с новой сессией.
- Частичное выполнение остаётся partial; без оценки полезности итог и полезность не выдумываются. Состояние сохраняется после повторного открытия.
- Три контрольных рискованных текста останавливаются до API, без создания плана.
- Прямая просьба дать посильный шаг в контексте задачи получает конкретный подготовительный шаг даже при fallback, вместо возврата к меню. Предложение не создаёт выполненную попытку.

Первый backend-прогон выявил последнее нарушение: «Дайте один посильный шаг» не распознавалось как прямой запрос, fallback возвращал меню. Распознавание расширено, регрессия проверена для всех трёх тренеров без API и повторным live backend-прогоном.

## Воспроизводимость и ограничения

Команда: `node scripts/run-live-backend-qa.mjs --live --budget-usd=5 --label=UNIQUE_LABEL`.

Запуск требует согласованного локального секрета и существующего ledger; повторный отчёт не перезаписывается. Общий предел 225 запросов, на прогон не более 12. Повторные API-запросы автоматически не выполняются. Секрет остаётся в родительском процессе; Worker получает только локальный proxy с отдельным временным capability. Тестовый Worker не подключён к production entrypoint.

JSON-транскрипты baseline и after-direct-fix сохранены локально вне Git. Локальный полный verify после исправления: 18 Python + 119 Node тестов, lint/typecheck, D1 smoke/integration/recovery, build, HTTP и maintenance прошли.

Это backend integration, а не проверка реального браузера, production auth-route, микрофона или телефона. Передача поправки в контекст не доказывает клиническую корректность ответа. Успешные safety-примеры не гарантируют распознавание всех рисков. Экспертная оценка, production backup/restore, настройки публикации и решение о релизе остаются открытыми. Production не изменён.

## Как воспроизвести S07

Собрать текущий кандидат через `npm run build`, затем `npm run test:pilot-ui`. Требуется Playwright/Chromium; при необходимости задать локальный `SKILLER_CHROMIUM_EXECUTABLE`. Для управляемого разрыва запроса в этом сценарии service worker браузера заблокирован; это не проверка PWA/offline-кэша. Тест запускает только локальный Worker с AI_DISABLED и временной тестовой D1, использует настоящую гостевую сессию и удаляет тестовое хранилище после завершения.

Прогон намеренно длится несколько минут: четыре напоминания назначаются минимум на минуту вперёд и становятся видимыми по настоящим серверным часам и обычному polling. Во время ожидания проверяются оборванный POST и обновление задачи из другого окна. Следовательно, результат не является имитацией успешной доставки через тестовый endpoint. Playwright 390 px не заменяет реальный телефон.

Команда отделена от обычного verify, чтобы не навязывать Chromium/ожидание реального срока каждому unit/CI-прогону. Отдельный проход обязателен для технической приёмки изменённого reminder UI; CI сам по себе этот браузерный сценарий не выполняет.

## Минимальный пакет для решения о выпуске

1. Утверждённый кандидат с зелёным CI и всеми применимыми техническими сценариями выше.
2. Проверка настоящей копии данных в изолированной среде, production D1/ingress и отключение внешнего автодеплоя.
3. Вердикт психолога по живым синтетическим диалогам и проверка реального телефона/голоса.
4. Утверждённый оффер, права доступа, фактическая схема оплаты и пользовательские условия, если запускается продажа.
5. Выбор внешнего reminder-канала и его проверка либо явный выпуск только с входящими открытого приложения. Внешнюю доставку не включать в обещания до приёмки.
6. Контроль расходов и наблюдение ошибок; затем конкретный SHA, утверждённый deploy и post-deploy smoke S08.

Сложная геймификация и полный объём трёх программ не входят в эти блокирующие условия MVP. Наличие перечисленных открытых гейтов не означает, что их проверка уже выполнена.

# SKILLER — сводный аудит требований и реализации

Дата проверки: 26.09.2026  
Источник требований: `SKILLER_TZ_25_09_2026(1).docx`, Frozen MVP v1.0, PATCH 1.1, ручная обратная связь 15–26.09.2026.  
Проверенная ветка: `feat/conversation-relationship-layer`, GitHub commit `4a889cf`.  

## Итог

Техническое ядро conversation-first MVP работает: сохраняет разговоры, проводит простой и подробный разбор, использует Skill Engine, создаёт open loop, возвращается к нему, различает четыре исхода, обновляет память и имеет детерминированный safety/fallback. Полный `npm run verify` проходит: 84 core-теста, D1 smoke, D1 integration и production build.

Новая версия ещё не готова к новому пилоту по ТЗ от 25.09. Главные разрывы: утверждённый дизайн не перенесён в рабочий интерфейс, кризисный режим не отделён от автоматического safety в рабочем UI, нет Reset profile, правила «один новый навык в день», locale-layer, push-напоминаний, нового дневника, отдельного экрана модели пользователя и пилотного dashboard. Последний commit не развёрнут в production.

Статусы: **DONE** — работает в основном продукте; **PARTIAL** — часть работает или есть только прототип; **MISSING** — реализации нет; **DELIVERY** — код готов, но не развёрнут или не проверен вручную.

## Что действительно работает end to end

1. Пользователь проходит onboarding и выбирает тренера.
2. Пишет или диктует реальную ситуацию.
3. Safety проверяется детерминированно и имеет приоритет над LLM.
4. Система проводит простой или подробный анализ и просит подтвердить гипотезу.
5. В подробном варианте собирается и редактируется поведенческая цепочка.
6. Пользователь выбирает точку вмешательства, Skill Engine выбирает допустимую практику.
7. Создаются plan и persistent open loop.
8. Пользователь выполняет действие или возвращается позже.
9. DONE, PARTIAL, NOT_DONE и SKILL_REJECTED запускают разные разговорные ветки.
10. Сохраняются success factor, chain break, missing link или rejection reason.
11. Следующий разговор получает релевантную behavioral memory и может продолжить прошлый эпизод.
12. Данные пишутся в D1, события идут через идемпотентный event writer; экспорт в Sheets готов технически.

3. Убрать form-first блоки из основного composer.

1. Reset profile.
2. Один новый навык в день.

5. Google Sheets ID, dashboard и DBT_PILOT_01.

### Спринт D — возврат и установка

1. Permission flow для push и расписание follow-up.
2. Email как опциональный резервный канал.
3. Полный manual smoke на реальном телефоне и desktop.
